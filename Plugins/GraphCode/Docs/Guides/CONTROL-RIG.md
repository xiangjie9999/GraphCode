# Author a Control Rig on a prepared character

Use `.gcrig` to prepare bones, skin, anatomical axes and named controls. Request a native authoring starter alongside the skeletal mesh:

```gcrig
gcrig 1 mesh:/Game/Characters/SM_Character into:/Game/Characters override:true
build {
  SK_Character = skeletal_mesh()
  CR_Character = control_rig()
}
```

Retain the source's actual bones, controls and other blocks. Without a `control_rig()` output, applying that source does not create or refresh a starter. Removing the output declaration does not delete an existing asset.

Each named `control(...)` exposes two instance-editable floats: its name (0–1 across calibrated endpoints) and `<Name>_Weight` (0–1 blending from the incoming pose). Weights default to zero. Rotation uses recorded bone-local axes and degrees; translation uses centimetres. Controls execute in source order. Later controls on the same bone blend over the preceding result.

`GCRig_Control_<Name>` is a native mutable function with `Value` and `Weight` inputs. `GCRig_ApplyControls` reads the member variables and calls the control functions. The solve model starts with `Begin` and `ApplyControls`; extend its wiring before or after this call. The solve wiring is seeded once and preserved on regeneration.

`rig {}` carries readable source, spaces, `axes {}`, `calibration {}`, `chains {}` and resolved limits. `hierarchy {}` carries prepared reference transforms. Both are read-only context. Chain targets become inputs only when authored logic consumes them. A new `kind:control_rig` recipe can instead set `PreviewSkeletalMesh` in `settings {}` to seed from a prepared mesh; source-only chain/limit information is not invented.

## Author variables and logic

Read the asset first. Retain its envelope, graph names and unedited blocks. A whole-document apply validates changed `properties` and `graph` together before editing either:

```gc
properties {
  Lift: float = 0 [instance_editable, category="Motion", tooltip="Height in centimetres"]
}
graph {
  solve RigVMModel {
    ReadLift = variable() [variable=Lift, getter=true]
    ApplyControls = call() [function=GCRig_ApplyControls] : ->Raise
    Raise = SetTranslation(Value.Z=ReadLift.Value, Item.Name=root, Space=LocalSpace)
  }
}
```

Use the actual solve and bone names from the read. Arguments carry literals and data links. Brackets carry off-pin node state. Execution follows `: ->Next`; name exact native pins when needed, such as `: ExecutePin->Next.ExecutePin`. An omitted execution-pin name requires exactly one eligible pin in that direction. Comments use `Note = comment("Explanation")`.

Members and locals use shared GraphCode types such as `float`, `int`, `name`, `string`, `Vector`, `Transform` and `TArray<float>`. Member flags include `instance_editable`, `blueprint_read_only`, `category` and `tooltip`; `!flag` explicitly disables a flag.

```gc
function Double {
  input {
    Value: float = 0
  }
  output {
    Result: float = 0
  }
  local Scale: float = 2
  Entry = entry()
  Twice = MathFloatMul(A=Entry.Value, B=2)
  Return = return(Result=Twice.Result)
}
```

Mutable functions use `function Name [mutable]`. Native RigVM pins that are both input and output belong in `io {}`. Preserve projected template `notation`, resolved `!types[]` and linked-array `size.Pin` fields.

Patch preserves unmentioned nodes, graphs and members. Each supplied node completely states its data inputs, defaults and outgoing execution links; incoming execution from unmentioned nodes survives. `delete Name` inside a graph removes that node; in `properties`, it removes that member. Snapshot replaces only supplied blocks, requires every existing graph declaration, and refuses graph content the reader cannot represent. Settings use `reset Path` under patch; snapshot resets absent settings.

Dry-run compiles a private native candidate. Real writes validate before changing the live rig and retain rollback on failure. Test the resulting behavior on the character; compilation alone does not establish animation quality.

## Regenerate from the source

The `.gcrig` header defaults to `override:true`. Each apply replaces only functions recorded as generated by that same source, including native edits inside those functions. Replacement does not depend on detecting edits or changed calibration.

Use header `override:false` to preserve an existing output. To preserve one control while others regenerate:

```gcrig
controls {
  Grip = control(hand.fold=(0, 75)) [!override]
}
```

`[override]` is the individual default. Header false takes precedence. New outputs and newly added controls still receive initial generation. Removing an exception resumes replacement; native editing never adds the exception back.

Unrelated functions, authored solve wiring, hierarchy additions, settings and existing member defaults/visibility always survive. Names alone do not confer ownership: a function called `GCRig_Something` remains authored unless the source's generation record owns it. A protected function retains its previous setup under `preserved FunctionName {}` alongside current source context.

The downstream `program` override block is retired. Rigs without a generated-function record are not replaced wholesale. Changed prepared anatomy, removed controls, incompatible interfaces and name collisions require deliberate reconciliation or a new output name.
