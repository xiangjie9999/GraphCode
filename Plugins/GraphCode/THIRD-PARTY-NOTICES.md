**Every file under `Source/GraphCodeMCP/` carries a `// Copyright Natali Caggiano` header, and
those headers must stay.** Removing them is a licence violation. If you add a genuinely new file
to that module — one whose content is GraphCode Sdn Bhd's own work rather than a modification of
upstream's — give it a GraphCode Sdn Bhd header instead; the two can sit side by side in one module, and
mislabelling in either direction is the thing to avoid.

### What was changed

Vendored at upstream commit `558f29aa` and modified since. As of **2026-08-27** the two
substantive divergences are:

- **The module moved and was renamed.** It was the `UnrealClaude` plugin's own module; it is now
  `GraphCodeMCP`, a module of this plugin. The dependency runs one way — `GraphCodeMCP` →
  `GraphCode`, never back — because `.gc` sidecars must keep working with no Node process and no
  MCP at all.
- **The in-editor Claude Assistant was dropped, not ported.** Upstream ships a chat panel, a
  toolbar button, a Quick Ask window and a CLI runner. What this product ships is a *bridge*, which
  a customer points their own MCP client at, so a second provider-specific way in was surface
  nobody had asked for. Seventeen files and roughly 4,500 lines were removed, along with the
  module's dependency on the chat widgets, `ToolMenus` and `WorkspaceMenuStructure`.

Much of what is under `Source/GraphCodeMCP/MCP/Tools/` is GraphCode Sdn Bhd's own work — the `gc_*` verbs
and their adapters were written here against upstream's registry, not inherited from it.

### The bridge's own dependency

`Resources/mcp-bridge/vendor/mcp-sdk.mjs` is Anthropic's
[`@modelcontextprotocol/sdk`](https://github.com/modelcontextprotocol/typescript-sdk) (MIT),
bundled to a single file so that a customer never has to run `npm install`. It is generated by
`npm run vendor:sdk` and is not hand-edited. Its licence travels inside the bundle.

## Human gait reference data — the WalkAndRun example

The measured walk and run (`Walk.gcmove`, `Run.gcmove`, written by `Tools/Research/Gait/make_gait_clip.py`; in this
project under `Content/__MCPTests/Gait_20261007/Runner`, joining `Docs/Examples/WalkAndRun` once their acceptance
measurements pass) are built from published human motion measurements, so a character's legs, trunk and arms move as
measured people do. The numbers are transformed by GraphCode (below); the original authors
do not endorse these adaptations. Every `.gcmove` built from them names its source and each change in its header.

**Walking: OpenSim Moco / Rajagopal walking data.** Modified numerical references from OpenSim Moco's
`example3DWalking/coordinates.sto` and `grf_walk.mot`, opensim-org/opensim-core commit
`9432f35ebde0ad0c619af02d308b151d010eadb2`:
https://github.com/opensim-org/opensim-core/tree/9432f35ebde0ad0c619af02d308b151d010eadb2/OpenSim/Examples/Moco/example3DWalking
The coordinate data originate in Rajagopal et al. (2016), "Full-Body Musculoskeletal Model for Muscle-Driven
Simulation of Human Gait", https://doi.org/10.1109/TBME.2016.2586891, distributed with the sample simulations at
https://simtk.org/projects/full_body under the MIT License, Copyright (c) 2015, Stanford University. The OpenSim
distribution is licensed under the Apache License 2.0; its NOTICE records Copyright (c) 2005-2017 Stanford University
and the Authors. The complete MIT notice, Apache licence and OpenSim NOTICE ship beside the example as
`LICENSE.RajagopalData.txt`, `LICENSE.OpenSim.txt` and `NOTICE.OpenSim.txt`.

**Running: Hamner, Seth and Delp (2010).** Derived from the subject02 running take, "Muscle contributions to
propulsion and support during running", Journal of Biomechanics, https://doi.org/10.1016/j.jbiomech.2010.06.025,
files `Pipelines/Hamner/outputReference/ResultsIK/subject02_running_ik.mot` and `Pipelines/Hamner/subject02_running_grf.mot`
in opensim-org/opensim-models, commit `d9b05d470b1a481c222372c85b75772faf8f7792`. That repository states no licence
for these files; GraphCode uses the measured values as factual reference numbers and credits their source here.

**What GraphCode changed, for both.** It selects one stride (right foot strike to the next), normalizes and resamples
it, converts radians to degrees and metres to centimetres, derives support timing from force crossings (20 N for the
run), maps each anatomical angle onto rig controls with the signs measured on the target rig, spreads each curve's
end-to-start gap linearly so it loops, shares lumbar motion over three spine joints, lowers the T-pose arms, and where
the target body is bulkier than the measured one widens the step or the arm carriage by a few degrees.
